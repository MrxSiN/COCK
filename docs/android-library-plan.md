# Source-sized Android ELF component batch

Current contract after the physical-device repair: the builder consumes u16 guest native-byte count, exactly 220 bytes from `src/android_activity_callback.bf`, exact BF guest entry bytes and A5. The callback export size and padding to the unchanged guest address follow this size. Producer identity/admission and physical closure remain caller preconditions. The u16 native budget is a component representation, not a universal app limit. A bad guard leaves a provisional prefix that must not publish. See [device evidence](windows-device-evidence.md).

Emit ELF64 ET_DYN EM_AARCH64 with real `ANativeActivity_onCreate` and `cock_guest_run_v1` exports and `__android_log_write` GLOB_DAT relocation via `liblog.so`. RX ends at 0x1000 plus actual guest size. RW file offset is the next 16-KiB boundary, while virtual address is fixed 0x100000; its first 256 file bytes hold GOT and dynamic metadata and BSS extends through the 96-byte invocation state at 0x104000. RELRO covers the import/dynamic page and leaves the next state page writable. There is no WX segment or text relocation. Include nonexecuting stack and correct ELF section metadata because modern Android validates section headers.

Fixed metadata addresses: strings 0x180 size 91, four symbols 0x200 size 96, SysV hash 0x260 size 28, one RELA 0x280 size 24, section names 0x300 size 68, ten section headers 0x400 size 640, callback 0x800 size 220, guest 0x1000 variable. Dynamic table at 0x100010 size 224 has NEEDED, HASH, STRTAB, SYMTAB, STRSZ, SYMENT, SONAME, RELA, RELASZ, RELAENT, BIND_NOW, FLAGS, FLAGS_1 and NULL. Strings are null, callback, guest, `libcockstagea.so`, `liblog.so`, log import. Section names identify text, dynstr, dynsym, hash, rela.dyn, dynamic, got, bss and shstrtab.

Tests independently inspect headers, sections, exports, dynamic symbols, relocation target/type/symbol, hardening, string boundaries and 16-KiB congruence with LLVM readelf. Extract both text regions and compare against unchanged BF-produced native bytes. Check multiple source sizes across a 16-KiB file boundary, maximum representable input, exact reproducibility and missing guard's incomplete output. Execute the real builder through BF-in-BF for one source. Existing CPU guest/callback tests verify native routines separately. No conventional assembler or linker may supply these production bytes. External Android resource/debug packaging/signature tools are development-only and do not establish Stage D. A candidate library is not a passed Android loader or device test.
