# Six cell Brainfuck in Brainfuck interpreter evidence

Date: 2026-10-24. Status: **diagnostic execution component passed; Stage A acceptance not passed**.

## Implementation and owned execution

`src/bf_in_bf_six_cell.bf` is newly drafted eight-command BF source with safe printable annotations. It interprets the guest BF instruction stream as data. The interpreter uses 12 outer tape cells per guest instruction record and carries six guest data bytes, the guest pointer index and loop depth when advancing its virtual PC. It implements real guest `+`, `-`, `<`, `>`, `[`, `]`, `.`, and `,` dispatch within the bounded six-cell guest tape, including matched nested-loop scans and byte-oriented I/O. It is not an AOT source substitution.

Its diagnostic input grammar is a sequence of `(one nonzero u8 count, exactly that many BF command bytes)` records, followed by one zero count, then raw guest stdin bytes. The complete program can exceed 255 source bytes by using repeated records. This **is not** `COCK-FRAME-v1`, `COCK-BUILD-INPUT-v1` or `COCK-HOST-IO-v1`; the input requires external exact byte-count, complete-source validation and trusted closure to be usable in an accepted workflow.

Current guest-cell addresses are exactly 0 through 5. This is an experimental resource-bounded interpreter, not the scalable/full COCK guest tape. The original `src/bf_in_bf.bf` remains preserved, and the licensed BF reference remains independent. The added kernel does not yet self-interpret its own full source because the kernel itself requires a larger guest tape. The full nested compiler proof is not established.

## Reproduce the fixture diagnostics

Run from the repository root using an independently provisioned outside-repository BF evaluator with 8-bit wrapping cells, binary stdin/stdout, verified EOF-zero behavior, growing outer tape and sufficient execution budget. An illustrative invocation (assuming the diagnostic evaluator is externally installed) is:

```text
cock-bf-diagnostic src/bf_in_bf_six_cell.bf 2500000000 < fixtures/six_cell/original_tiny_app_a.input.bin > /tmp/cock-candidate.raw
cmp /tmp/cock-candidate.raw artifacts/tiny_app_a.aarch64.raw
```

The command is documentation only; no shell, Python, C or foreign-language executable source is checked into COCK. The local test executor in this environment was a provisional C diagnostic at `/tmp/cock_bf_diag`, not independently qualified as the permitted root BF bootstrap. The recorded full fixture inventory, source SHA256 and raw outputs are in `six-cell-interpreter-evidence.json`.

## Known negative proof failures — not acceptance passes

- `>>>>>>+.` walks beyond address 5. The current prototype silently produces zero stdout with a success exit instead of returning a structured configured logical-cell-budget violation.
- `<+.` moves left at guest address 0. The current prototype silently produces no stdout with a success exit instead of a `LEFT_BOUNDARY` guest trap.
- `+.[` contains an unmatched opening bracket after output-capable commands. Without a complete external source preflight, the kernel prints `01` and exits instead of rejecting the entire source before any guest effects.

These are **known correctness gaps**, not tests that passed. Arbitrary/untrusted guest programs must not be admitted to this interpreter. The current compiler sources were separately inspected for maximum guest tape address 5, and the six preserved compiler regression outputs confirm behavior only on those admitted examples. Source preflight and exact closure are not integrated.

## Testing and provenance boundaries

- Positive reference checks used `src/bf_in_bf_reference.bf` (separately attributed under CC BY-SA) running under the same outside-repository C diagnostic BF evaluator. This is differential component evidence, not fully independent bootstrap qualification.
- A temporary outside-repository Python drafting and diagnostic aid was used to compose repetitive BF instruction passages and generate inert binary fixtures. No generated Python script or executable DSL was included in the repository. Strict end-to-end BF-only authorship process provenance therefore remains **not certified**, even though the checked-in executable source consists only of BF commands.
- The originally attempted randomized suite contained six nonterminating or fuel-exhausting test programs involving unguarded even-step loops. Those fixtures were corrected, and the final finite 93-case differential batch was rerun and passed. An interrupted preliminary run is not counted as passed.
- The 6-cell implementation currently lacks bounded runtime guest-fuel accounting, loop-depth overflow handling, native trace offsets, declared logical budget trap priority, scalable tape storage, complete-source preflight, verified independent host process/stream closure, and full nested self-interpretation.
- Android SDK/emulator/device tests, ELF generation and debug APK packaging remain **DEFERRED / NOT RUN**.

**Next required milestone:** make guest pointer and logical budget violations explicit rather than silent, implement trustworthy preflight/closure and a self-hosted interpreter with enough guest tape/resources to run itself as an inner guest and then the complete mini compiler.
