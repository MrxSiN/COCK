# Stage A sixteen bit guest execution step evidence

**Status:** LOCAL DIAGNOSTIC PASS only. Stage A self hosting acceptance remains blocked. Android stays deferred.

## Change implemented

`src/source_pc_16bit_guest_step.bf` is a Brainfuck-only development component with **34,246 executable commands** and SHA-256 `fa90883c9a9b7f4dce3d464783f006d08bc0f9d08b326c6ed454318c0c169be3`. The exact input and output records are defined in `docs/source-pc-16bit-guest-step-plan.md`.

It combines a 16-bit source command position and fuel decrement with **actual local effects** for `+`, `-`, `<`, `>`, `.`, `,`, and control-flow decisions for `[` and `]`. Values `00` and `FF` are ordinary guest input/output bytes. Results express output as a flag and a byte, **not** an authoritative raw guest stdout stream. Invalid opcodes and invalid input presence flags return status 13 before charging fuel. An empty fuel budget returns 6 without guest effects. Left boundary returns 4 and logical right boundary returns 5 after charging one executed instruction but without pointer movement. An unrepresentable next PC returns 10 and does not perform guest cell effects. Fatal status leaves the returned PC at its original position.

**Important:** the current cell and pointer are supplied for each step and returned in the response; this program does not retain a multi-cell guest tape. It does not own source instruction selection, bracket pairing, or raw stdin read authority. Consequently even matching all compiler step positions is **not equivalent** to executing the compiler under this component.

## Negative diagnostic evidence

- **Untrusted bracket target:** changing an opening bracket's supplied partner from 100 to 200 changed the returned next PC from 101 to 201 while both records reported success. A BF-owned bracket map tied to the exact admitted source must be authoritative.
- **Truncated record:** omitting the final input byte from a non-input opcode produced the same output under the diagnostic evaluator because its EOF rule supplies zero. Trusted actual byte count and stream completion remain mandatory.
- **Trailing data:** adding an unconsumed extra byte after the declared record produced the same response and successful process exit. The BF program does not attest complete stream closure.
- **Invalid pointer state:** a caller-supplied pointer greater than the declared logical budget was not independently rejected for arithmetic. The caller must currently validate step-state invariants; this is not a safe dispatcher for arbitrary guest input.
- **Invalid input presence:** the new pre-execution check correctly returned status 13 for the `,` opcode with a nonboolean input-presence field.

Exact hexadecimal observations and the evaluator's consumed byte count are in `docs/source-pc-16bit-guest-step-evidence.json`.

## Nonpromotion decision

The existing 16-bit source ledger, fetch and fuel branch and this new step component **have not yet been combined into a self-contained BF interpreter**. There is no internal persistent guest tape, trusted complete-source admission or host transport authority. The strict BF-only **development-process authorship** gate is NOT CERTIFIED because an external layout/drafting aid was used and kept outside the repository. It did not run in the production code path, but that distinction does not satisfy the stronger process rule in the specification.

The next integrated slice must own source fetch, correct bracket matching, instruction execution and guest tape under one BF-authored dispatcher and then run the complete real compiler. The full identical-interpreter nested compiler proof remains NOT VERIFIED. Android SDK, emulator, ELF/APK and device tests remain DEFERRED.
