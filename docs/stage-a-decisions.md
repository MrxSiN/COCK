# Stage A feasibility and scope decision

Status: **development in progress, acceptance BLOCKED**. All artifacts below are development inputs, not production releases. The complete current design is [the full Stage A draft](stage-a-full-draft.md). Installed tool/runtime evidence is [the cloud Android report](cloud-android-environment.md); old tools-unavailable observations are superseded below.

| Item | Decision | Evidence status |

| Android NDK and platform tools | NDK r28c, adb, emulator and build tools 35.0.0 installed | Tool version/install evidence in cloud report; app build NOT RUN |

| Android log import | `__android_log_write` via `liblog` | Defined service, not generated or linked |
| Loading and lifecycle | Android shared object with native entry and verified callback return | NOT IMPLEMENTED |
| Main-thread safety | Short loop-free app source; bounded synchronous execution only after callback implementation | Design only |
| Debug APK packaging | External SDK packaging and disposable debug signing only | NOT RUN |
| Release signing | BF-native only, requires independent security gate | UNSUPPORTED |

The raw AArch64 function bytes generated by `src/mini_compiler.bf` are **not** an ELF shared object or installable Android application. The current output returns the guest cell value in `w0`, but does not create context and result headers, perform Android logging, or provide the OS loader callback. An Android integration may not be claimed from these raw bytes.

Official design contracts: https://developer.android.com/reference/android/app/NativeActivity ; https://developer.android.com/ndk/reference/group/native-activity ; https://developer.android.com/ndk/reference/group/logging .

## Restricted development component

The present code-generation component consumes only **already validated**, exact, normalized input bytes whose command stream is one or more `+` or `-` commands followed by one final `.` command, with source/transport closure certified independently. It emits AArch64 machine-code words as raw little-endian bytes. Every increment/decrement becomes a native instruction plus an unsigned byte truncate, rather than an opaque template of an entire app. The guest starts at zero, is 8-bit wrapping and has no pointer movement, loops or guest input. The printable-output requirement is checked by a future source-admission gate; the current compiler does not verify it itself.

The current BF components use EOF returning `0` to end source ingestion. This is **not sufficient** to verify an annotated `.bf` file has no embedded NUL, no illegal suffix or full closure. Consequently the component must not be exposed as an unrestricted compiler or counted as completing `COCK` source preflight. A strict length-bearing BF-authored preflight/input authority remains mandatory.

## Native instruction contract

`mini_compiler.bf` emits the following raw AArch64 instructions, each little endian:

| Operation | Bytes | Effect |
|---|---|---|
| initialize | `00 00 80 52` | `mov w0, #0` |
| increment | `00 04 00 11` | `add w0, w0, #1` |
| decrement | `00 04 00 51` | `sub w0, w0, #1` |
| constrain to 8 bits | `00 1C 00 53` | `ubfm w0, w0, #0, #7` |
| return | `C0 03 5F D6` | `ret` |

Each input arithmetic command generates the appropriate arithmetic word *and* the unsigned byte truncation word. The final `.` is interpreted as a deferred return of the single byte from `w0` because the admitted application subset has no other output commands. Unsupported source must be denied by preflight, not processed by this raw generator.

## Feasibility decision

The declared Android loader entry is supported in the published Android API and installed NDK header. Its native callback is **not** the internal two-pointer COCK guest entry. SDK/NDK/evaluator tools are installed, but no stable ARM64-capable execution target or BF-generated bridge/ELF exists to prove native loading, import resolution, logging or responsive callback execution. Therefore independent BF component development can proceed, but **Android proof A01-A14 is BLOCKED**. No fallback desktop ELF is an Android acceptance substitute.
