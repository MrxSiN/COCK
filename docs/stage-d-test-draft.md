| ZIP/CRC | Stored zero/binary entries, canonical dynamic file set, duplicate/path/CRC/size/local-central mismatch, alignment padding, representation overflow, unsupported ZIP64/compression, malformed/trailing EOCD, exact native bytes |

| v2 scheme | Exact full independent signed fixture, every region and 1-MiB chunk boundary, all nested lengths/IDs/algorithm lists/certificates, wrong digest/offset/padding, duplicate signers and signing-block sizes |
| Tampering | BF-generated one-byte changes in native/asset/manifest/local metadata/central directory/EOCD protected regions, signature/signed-data/certificate/signing-block changes, truncation/junk/reorder/realignment; each rejected for the recorded reason |
| Authority | Unknown process/write/close, early OK, missing END, wrong staged/final hash, partial signing and interrupted publication; prior valid artifact retained, no completed failed package |
| Ownership | Repository/executable audit, no host packaging/sign/hash semantic production path, native bytes and every executable entry BF-produced; debug fallback named separately |
| Device | Actual selected API-35 ARM64/bridge load, separate tested 4-KiB/16-KiB rows, signature install acceptance, both source-distinct mini apps and held-out application, lifecycle/observation regressions |
| Security | Disposable secrets isolated/excluded from repo/log/cache/fixtures; threat-model/custody/side-channel/entropy review states explicit; no fabricated secure-erasure claim |

Externally installed `apksigner verify`, independent certificate/hash tools, ZIP inspectors, Android resource decoders, LLVM and device tools may inspect/reject exact BF-generated bytes. They must not generate/repair/sign the production candidate under test. Record unmodified input/output hashes and tool versions. Require full-file signature verification and expected failure for each deliberate mutation; an already invalid package or unavailable installer cannot be counted as a successful tamper test.

The independently verified bytes must equal the bytes staged, published and installed. Capture unsigned/final hashes, certificate fingerprint without secrets, scheme/API policy, complete entry inventory, native extraction equality, source/compiler/interpreter identities, exact command exits and device/build/page size. Perform normal compiler-as-BF-guest and required identical-interpreter actual compiler checks; package success cannot cover missing self-hosting. Preserve Stage A/B/C regressions when shared sources change.

Only after correctness/device/ownership gates pass, measure at least three equivalent cold/warm runs: binary resources, CRC/ZIP, digest/signature, whole BF package/build and independent verification separately. Report wall/CPU time, peak memory where available, native/resource/ZIP/padding/signing bytes and total APK/installed size. Include small input setup overhead and larger assets/signature chunk boundaries. Optimization is optional after the accepted O0 baseline and needs complete crypto/tamper/device regression plus rollback. No speed/size value is supplied here.

D01–D08 closure can support a **fully BF-authored signed direct-install APK** only for tested targets and exact ownership/verification scope. It does not by itself authorize release keys, demonstrate safe secret custody, certify AAB/Play or mark untested platforms compatible. Absent required source/KAT/device/close facts remains NOT RUN/BLOCKED, with explicit errors rather than weakened expected results.
